# engine — граф сценария и расчёты

Разбирает сценарий и считает наборы данных и показатели за отчётный период.

- `analyze(scenario, registry, schemas)` — проверка без данных: плагины, параметры,
  ссылки, столбцы, порядок формул (и круговые ссылки). Все ошибки сразу, с узлом, в котором
  они найдены. `column_usage` — какие столбцы источника нужны сценарию (для `schema`).
- `execute(plan, registry, history, period, workdir)` — расчёт. История приходит через
  `HistoryProvider` из контрактов: движок не знает о модуле `history` и о хранилище.

Как считается:

1. Вход — действующая история, обрезанная по концу отчётного периода, и шаги по порядку.
   Если все шаги построчные, нижняя граница нужных окон проталкивается в чтение истории.
   Результат входа пишется в `workdir/inputs/<вход>.parquet`.
2. Набор — окно, условие, группировка (для дат — по месяцам, кварталам, …), агрегаты,
   сортировка, топ-N. Показатель — агрегат в своём окне или формула из других показателей.
3. Ошибка в узле помечает «не считался» только зависящие от него узлы; остальные
   считаются. Пропуски в загрузках за нужные окна — предупреждения.

Формулы пишутся на SQL (диалект DuckDB) и переводятся в выражения Polars (`SqlTranslator`).
Деление на ноль даёт пусто, а не ошибку.

Запуск отдельно — на готовой истории (например, от `python -m autogenerator.history --out`):

```
uv run python -m autogenerator.engine examples/sales/scenario.yaml --data история --period 2026-03 --out итоги
```

Тесты модуля: `uv run agen test engine` (или `uv run pytest packages/engine`).
