# readers-std — встроенные читатели CSV и Excel

Плагины-читатели. Каждый отдаёт файл порциями, **все столбцы — текстом**: типы выводит
и приводит `ingest`, одинаково для всех форматов.

- `csv` — потоковое чтение: файл режется на порции по 32 МБ по концу строки (с учётом
  кавычек и переносов внутри них), каждую порцию разбирает Polars в несколько потоков,
  следующая читается заранее. В памяти — пара порций, размер файла не ограничен.
  - Кодировка: UTF-8 с BOM и без, Windows-1251 — по началу, середине и концу файла.
    UTF-8 проверяется строго по всему файлу; ошибка называет строку и предлагает
    `--encoding cp1251`. Windows-1251 перекодируется порциями в памяти.
  - Разделитель — тот, что даёт одинаковое число полей (`;`, табуляция, `|`, `,`).
  - Строка заголовков ищется сама: первая строка, где большинство ячеек — текст (над шапкой
    бывает заголовок отчёта). Можно задать `header_row`.
  - Непарные кавычки — ошибка с номером строки; если кавычки в данных — обычный символ
    (`24"`), помогает `quote: null` (`--no-quote`).
  - Строка, где полей больше, чем в шапке, — тоже ошибка с номером строки (той, где строка
    начинается). С `ragged: truncate` (`--ragged truncate`) лишние поля отбрасываются, а
    число таких строк и номер первой читатель сообщает замечанием (`note`), и оно попадает
    в итог загрузки. Разделитель в конце каждой строки (пустое лишнее поле) ошибкой не
    считается и читается без параметров. Разделитель внутри поля в кавычках лишним полем не
    считается. Лишние поля разбираются в запасные столбцы справа от шапки (один, если мало —
    восемь), поэтому скорость та же; порцию, где в строке лишних полей ещё больше, читатель
    проверяет построчно — в несколько раз медленнее.
  - Выборка для типов — начало, середина и конец файла; число строк оценивается по размеру.
- `xlsx` — fastexcel. Лист читается целиком (до 1 048 576 строк, около 3 ГБ памяти на
  1 млн × 30); шапка и листы находятся по первым строкам потоковым разбором XML
  (`xlsx_head.py`), без чтения листа. Если лист не указан, выгрузка — первый лист с
  данными и все следующие листы с такой же шапкой (так выгрузки больше миллиона строк
  делятся на листы). Даты Excel приходят текстом «2026-01-01 00:00:00». Перед чтением
  файл проверяется на zip-бомбу.
- `xls` — Excel 97–2003, по тем же правилам, что `xlsx`: шапка под параметрами отчёта,
  листы-продолжения, даты текстом. fastexcel читает книгу (до 65 536 строк на лист) целиком
  при открытии, первые строки листов берутся из неё же; zip-бомб у .xls не бывает.
  Двоичный файл Office, который fastexcel не открывает (документ Word, письмо Outlook,
  книга с паролем), читатель не берёт, и `ingest` отвечает, что это не книга Excel.
- `xlsb` — двоичная книга Excel, по тем же правилам, что `xlsx`. Файл — тоже zip и перед
  чтением так же проверяется на zip-бомбу, но листы в нём — двоичные записи, а не XML:
  первые строки листов даёт fastexcel, и лист ради них читается целиком, поэтому шапка и
  листы-продолжения у большой книги находятся дольше, чем у .xlsx. Zip без книги Excel
  (документ Word, архив с выгрузкой) читатели не берут, и `ingest` отвечает, что это не
  книга Excel, и предлагает распаковать архив.

Формат книги узнаётся по содержимому, а не по расширению и не по читателю источника:
.xlsx, сохранённый как .xls или .xlsb (и наоборот), читается как есть — и в источник,
созданный по выгрузке другого формата.

Пустые названия столбцов становятся «Столбец N», повторы — «Сумма (2)».

Зависит только от `contracts` (правило 3: плагины не знают о хозяевах).

Запуск отдельно — через `ingest`: `uv run python -m autogenerator.ingest файл.csv`.

Тесты модуля: `uv run agen test readers-std` (или `uv run pytest packages/readers-std`).
Тестовая выгрузка .xls — `tests/data/обращения.xls`; как она сделана — `tests/data/make_xls.py`.
Те же данные в .xlsb — `tests/data/обращения.xlsb`: такую книгу распространённые библиотеки
не пишут, и `tests/data/make_xlsb.py` собирает её вручную по спецификации MS-XLSB.
