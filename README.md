# Autogenerator

Автогенератор отчётных презентаций: выгрузки CSV и Excel за несколько периодов,
логика обработки и слайдов — и готовая .pptx в корпоративном шаблоне. Что и зачем —
в [PRD.md](PRD.md), как устроено — в [ARCHITECTURE.md](ARCHITECTURE.md).

Готовы этапы **M0 — сквозной каркас** (команда `agen run` собирает отчёт из примеров
в `examples/`), **M1 — данные** (большие CSV и Excel читаются потоком, источники и история
загрузок хранятся в папке данных, видны структура, профиль и покрытие периодов) и
**M2 — обработка**: все шаги MVP, формулы, шаги на SQL и Python, объединение входов,
наборы со сравнением периодов, сводные и топ-N с «Прочими», показатели всех видов и превью
любого узла (на больших данных — по выборке). Интерфейса пока нет: всё делается командой
`agen`.

## Как запустить

Нужен [uv](https://docs.astral.sh/uv/) (он сам поставит Python 3.12).

```
uv sync
uv run agen run examples/sales/scenario.yaml
```

В текущей папке появится `Отчёт_продажи_2026-03.pptx`: семь слайдов за март 2026 —
итоги с планом и сравнением с февралём, динамика квартала, регионы с долями, квартал,
лучшие менеджеры, план-факт по регионам.

Пример в `examples/sales/` устроен как настоящие выгрузки:

- `data/sales/` — продажи за январь, февраль и март (CSV в Windows-1251 с «;»);
  в феврале столбцы переименованы, в марте переставлены и добавлен лишний, есть
  дубликаты заказов и возвраты;
- `data/plan/` — план на квартал (Excel, заголовок отчёта над шапкой);
- `sources.yaml` — источники: столбцы, их типы и другие названия;
- `scenario.yaml` — сценарий: обработка, наборы данных (в том числе план-факт запросом SQL
  и динамика регионов сводной таблицей), показатели и слайды.

Шаблон `examples/templates/synthetic.pptx` синтетический. Данные и шаблон создаёт
`uv run python tools/make_examples.py`. Корпоративный шаблон в репозиторий не кладётся.

## Свои выгрузки: источники и история

Выгрузки загружаются в папку данных приложения: по умолчанию `%LOCALAPPDATA%\Autogenerator`
в Windows (другую задаёт `--home` или переменная `AGEN_HOME`). Там хранятся настройки
источников, все загрузки в Parquet и их история.

```
agen inspect Продажи_2026-01.csv                          # как прочитан файл, типы, профиль
agen source create sales --from Продажи_2026-01.csv       # источник по первой выгрузке
agen upload add sales Продажи_2026-01.csv Продажи_2026-02.csv Продажи_2026-03.csv
agen history sales                                        # загрузки, покрытие, пропуски
agen run сценарий.yaml -o отчёт.pptx                       # история берётся из папки данных
```

`agen source create` предлагает латинские id столбцов, типы и столбец периода; поправить
их можно в YAML (`agen source export sales -o sales.yaml`, затем `agen source import
sales.yaml`) — каждое изменение сохраняется новой версией. Столбец периода — тот, где
даты укладываются в один месяц. Если такого нет (выгрузка — срез на месяц, например
список клиентов), период берётся из имени файла («Feb», «январь», «2026-01») или
задаётся при загрузке: `agen upload add clients выгрузка.xlsx --period 2026-01`. Месяц в
названиях столбцов («… в январе», «… в апреле») сверке не мешает. Выгрузку из нескольких
файлов склеивает `agen upload add orders часть1.xlsx часть2.xlsx --concat`. Тот же файл второй раз не
загружается; загрузка с нераспознанными значениями ждёт проверки (`agen upload show`,
`agen upload accept`). Если у источника правило пересечения «ask», при повторной выгрузке
периода команда спросит, заменить его или добавить строки. Подробнее — `agen --help` и
README модулей [cli](packages/cli) и [storage](packages/storage).

Большие файлы: CSV на 10 млн строк × 30 столбцов загружается примерно за полторы минуты
и до 1 ГБ памяти, лист Excel на 1 млн строк — примерно за полминуты и до 3,5 ГБ (замер на
4 ядрах; `uv run python tools/bench_ingest.py`, в CI — на Windows).

## Логика и превью

Сценарий — YAML: шаги обработки каждого входа, наборы данных и показатели (что умеют
шаги — в README [steps-std](packages/steps-std), наборы и показатели — [engine](packages/engine)).
Результат любого узла виден без сборки презентации:

```
uv run agen preview examples/sales/scenario.yaml sales/positive_only   # вход после шага
uv run agen preview examples/sales/scenario.yaml dataset:region_months # динамика по месяцам
uv run agen preview examples/sales/scenario.yaml metric:revenue        # со сравнением с прошлым месяцем
```

Превью показывает первые строки и число строк до и после каждого шага. Если в истории входа
больше 500 тыс. строк, превью строится по выборке, которая сохраняет дубликаты и пары
ключей объединения, а числа помечаются «≈». На истории 5 × 10 млн строк превью шага
занимает около 0,3 с (`uv run python tools/bench_preview.py`, в CI — на Windows).
Когда история берётся из папки данных, результаты узлов кэшируются там же: повторный запуск
и превью на той же истории не пересчитывают обработку.

## Шаблон

Свой шаблон можно посмотреть глазами приложения, не меняя его:

```
uv run python -m autogenerator.theme "путь\к\шаблону.pptx" --layouts
```

## Модули

Каждый модуль — отдельный пакет в `packages/` со своим README, тестами и запуском
без остального приложения (`python -m autogenerator.<модуль>`). Модули обработки не
импортируют друг друга, плагины знают только контракты; это проверяет `uv run lint-imports`
(правила — в `pyproject.toml`, раздел `[tool.importlinter]`).

| Модуль | Что делает |
|---|---|
| [contracts](packages/contracts) | модели и интерфейсы, общие для всех |
| [plugin_host](packages/plugin_host) | находит и загружает плагины, изолирует сломанные |
| [readers-std](packages/readers-std) | плагины: чтение CSV и Excel |
| [ingest](packages/ingest) | структура файла, распознавание типов, запись загрузки |
| [schema](packages/schema) | сверка столбцов нового файла с источником, черновик источника |
| [history](packages/history) | история загрузок, правила пересечения, периоды, покрытие |
| [storage](packages/storage) | папка данных, метаданные в SQLite, файлы загрузок |
| [steps-std](packages/steps-std) | плагины: шаги обработки, окна, агрегаты |
| [engine](packages/engine) | граф сценария: обработка, наборы, показатели |
| [theme](packages/theme) | импорт шаблона: макеты, роли, слайды с метками |
| [blocks-std](packages/blocks-std) | плагины: текст, график, таблица |
| [render](packages/render) | сборка .pptx |
| [worker](packages/worker) | соединяет модули в задания «загрузить файл» и «собрать отчёт» |
| [api](packages/api) | фасад для своего кода и Jupyter, папка данных |
| [cli](packages/cli) | команда `agen` |

Разбирать модуль удобно на промежуточных данных настоящего запуска:

```
uv run agen run examples/sales/scenario.yaml --workdir отладка
uv run python -m autogenerator.history отладка/manifests/sales.json
uv run python -m autogenerator.render examples/sales/scenario.yaml --theme отладка/theme/manifest.json --data отладка/engine/outputs --period 2026-03 -o снова.pptx
```

## Проверки

```
uv run pytest            # все тесты
uv run agen test engine  # тесты одного модуля
uv run ruff check .      # стиль
uv run mypy              # типы
uv run lint-imports      # границы модулей
uv run python tools/bench_ingest.py   # бенчмарк загрузки (долго: генерирует 3 ГБ данных)
uv run python tools/bench_preview.py  # бенчмарк превью (история 50 млн строк, 1 ГБ)
```

Те же проверки идут в CI на Ubuntu и Windows; бенчмарки — отдельными заданиями на Windows.
Большие синтетические выгрузки для своих проверок делает `tools/make_big_data.py`.
