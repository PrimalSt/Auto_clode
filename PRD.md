# PRD: Autogenerator, автогенератор отчётных презентаций

> **Статус:** черновик v0.2 · **Дата:** 2026-09-29 · **Владелец:** God (@PrimalSt)
> **Связанный документ:** [ARCHITECTURE.md](ARCHITECTURE.md)
>
> Пункты с пометкой **[ОТКРЫТО №N]** зависят от ответа на уточняющий вопрос N (см. раздел 11). Пока в них заложен рекомендуемый вариант.

## 1. Проблема

Регулярные отчёты (еженедельные, ежемесячные) собираются вручную: взять выгрузку из учётной системы, почистить её в Excel (дубликаты, фильтры, нужный период), посчитать итоги, построить графики, перенести их в PowerPoint и подписать выводы. Каждый раз это одни и те же действия. Они отнимают время, и на любом шаге легко ошибиться.

## 2. Решение

Autogenerator запоминает структуру выгрузки и позволяет один раз описать **сценарий отчёта**: как чистить и фильтровать данные, что считать и что показывать на каждом слайде. Дальше достаточно загрузить новую выгрузку, и приложение само соберёт презентацию по сохранённому сценарию. Если структура файла изменилась (столбец переименовали, добавили или убрали), приложение покажет, что именно не совпало, и предложит сопоставление, которое запомнит на будущее.

Типовые операции настраиваются в визуальном конструкторе, без кода. Всё, чего в конструкторе нет, можно дописать на Python (pandas, python-pptx) прямо внутри сценария: код и визуальные шаги живут в одном сценарии, одинаково показываются в превью и одинаково запускаются.

Каждая загруженная выгрузка сохраняется в **истории** с отметкой периода («январь 2026», «февраль 2026»…). Поэтому слайды могут опираться не только на последнюю выгрузку, но и на накопленные данные: отчёт за квартал из трёх месячных выгрузок, динамика по месяцам, сравнение с прошлым периодом или с тем же месяцем год назад. Если сценарий поменялся, отчёт за любой прошлый период можно пересобрать из истории.

## 3. Цели и метрики успеха

| Цель | Метрика | Целевое значение для MVP |
|---|---|---|
| Экономия времени | Действия пользователя от загрузки новой выгрузки до готового .pptx | не больше 1 минуты |
| Повторяемость | Доля запусков, после которых презентацию не приходится править вручную | не меньше 90% |
| Предсказуемость | Одинаковая выгрузка и одинаковый сценарий дают одинаковую презентацию | 100% |
| Устойчивость к изменениям | Переименование, добавление, перестановка столбцов решаются сопоставлением без переделки сценария | 100% таких случаев |

## 4. Пользователи

**Основной пользователь:** аналитик, который регулярно готовит отчёты по выгрузкам из CRM, 1С, BI-систем, рекламных кабинетов и т. п. и умеет работать с Python: pandas для обработки данных, python-pptx для презентаций. Делать каждый отчёт кодом с нуля долго и тяжело, поэтому приложение должно:

- закрывать типовые операции (дубликаты, фильтры, группировки, стандартные графики) визуальным конструктором, чтобы не тратить на них код;
- давать спуститься на уровень кода там, где конструктора не хватает: свой шаг обработки на pandas, формула на SQL, свой блок слайда на python-pptx или matplotlib;
- показывать сценарий как текст, который можно прочитать, поправить, положить в git и запустить из командной строки.

Принцип: **конструктор по умолчанию, код по желанию.**

На старте пользователь один (владелец приложения). **[ОТКРЫТО №2]**

## 5. Ключевые понятия

| Термин | Что это |
|---|---|
| **Выгрузка** | Файл Excel (.xlsx, .xls) или CSV, который загружает пользователь |
| **Источник данных** | Одна регулярная выгрузка, например «Продажи из CRM»: её структура, сопоставления и история загрузок. На одном источнике может строиться несколько сценариев (еженедельный и квартальный отчёт) |
| **История** | Все загруженные выгрузки источника с их периодами. Для обработки они объединяются в одну таблицу |
| **Период выгрузки** | Отрезок времени, который покрывает выгрузка («январь 2026», «1–7 марта 2026»). Определяется по столбцу с датой, пользователь может поправить |
| **Отчётный период** | Период, за который собирается презентация. По умолчанию это период последней загруженной выгрузки |
| **Окно данных** | Какой отрезок истории берёт набор данных или показатель: отчётный период, прошлый период, квартал или год по отчётный период включительно, последние N периодов, вся история |
| **Структура** | Список столбцов выгрузки с типами данных (текст, число, дата, да/нет), форматами и параметрами чтения файла (лист, строка заголовков, кодировка, разделитель) |
| **Сценарий отчёта** | Вся логика отчёта поверх источника: обработка, наборы данных, показатели и слайды. Главная сущность приложения |
| **Обработка** | Упорядоченный список шагов очистки и фильтрации, применяемый к данным источника из истории |
| **Шаг** | Одна операция обработки: удалить дубликаты, отфильтровать, отсортировать, вычислить столбец и т. д. |
| **Шаг «Python»** | Шаг обработки, написанный кодом: функция получает таблицу pandas и возвращает таблицу. Стоит в том же списке, что и визуальные шаги |
| **Набор данных** | Именованная выборка из обработанных данных для графика или таблицы: группировка, агрегаты, сортировка, топ-N |
| **Показатель** | Одно число из данных (сумма, среднее, количество, изменение к прошлому периоду). Используется в тексте и KPI-карточках |
| **Оформление** | Дизайн-шаблон .pptx: макеты слайдов, шрифты, цвета. Корпоративный или встроенный |
| **Слайд** | Страница презентации: макет и блоки на нём |
| **Блок** | Элемент слайда: текст, график, таблица, KPI-карточка или блок с кодом |
| **Сопоставление** | Соответствие между столбцами новой выгрузки и столбцами источника |
| **Запуск** | Сборка презентации по сценарию за отчётный период. Результат: .pptx и журнал предупреждений |

## 6. Пользовательский путь

### 6.1. Первичная настройка (один раз на отчёт)

1. Пользователь создаёт источник данных и загружает образец выгрузки. Если есть выгрузки за прошлые периоды, их можно загрузить сразу пачкой, чтобы наполнить историю.
2. Приложение распознаёт лист, строку заголовков, кодировку и разделитель CSV, типы столбцов. Показывает превью строк и профиль каждого столбца. Пользователь при необходимости правит тип, формат даты или понятное название столбца и указывает столбец с датой, по которому определяется период выгрузки.
3. Пользователь создаёт сценарий на этом источнике.
4. Пользователь настраивает обработку: добавляет шаги из конструктора или пишет свой шаг на pandas и после каждого видит результат и число строк «было → стало».
5. Пользователь описывает наборы данных и показатели и для каждого выбирает окно данных: например, «выручка по регионам за отчётный месяц», «выручка по месяцам за квартал», «выручка за прошлый месяц» для сравнения.
6. Пользователь собирает слайды: выбирает макет, добавляет блоки, привязывает их к наборам и показателям, видит превью на данных из истории.
7. Сохраняет сценарий и скачивает пробную презентацию.

### 6.2. Регулярный запуск

1. Пользователь загружает новую выгрузку в источник.
2. Приложение сверяет её структуру с сохранённой:
   - всё совпало: сразу переходит к следующему шагу;
   - есть расхождения: показывает экран сопоставления с подсказками, пользователь подтверждает, сопоставление запоминается;
   - не хватает обязательного столбца, и замены не нашлось: объясняет, какие шаги и слайды от него зависят, и не запускает генерацию.
3. Приложение определяет период выгрузки и добавляет её в историю. Если данные за этот период уже есть, спрашивает, заменить их или дополнить.
4. Отчётным периодом становится период новой выгрузки. Приложение выполняет обработку, считает наборы и показатели по их окнам, собирает .pptx для выбранных сценариев источника.
5. Пользователь скачивает презентацию и смотрит журнал предупреждений (например: «фильтр по региону "Юг" не нашёл строк, график на слайде 4 пустой» или «нет данных за февраль, динамика за квартал неполная»).
6. Запуск сохраняется в истории запусков.

### 6.3. Отчёт за прошлый период

Пользователь выбирает сценарий и любой отчётный период из истории (например, «март 2026») и пересобирает презентацию. Данные позже этого периода не учитываются, поэтому результат такой, каким был бы отчёт в тот момент, но уже по текущей логике сценария.

Любой шаг можно отключить, переставить или удалить. После любого шага видно результат: первые строки и число строк до и после.

## 8. Нефункциональные требования

- **Производительность.** Для файла 100 тыс. строк × 50 столбцов: распознавание не дольше 5 с, превью шага не дольше 1 с, генерация отчёта не дольше 15 с. История из 24 таких выгрузок (2,4 млн строк) даёт отчёт не дольше 30 с. Файлы до 1 млн строк обрабатываются без падений, допустимо медленнее. **[ОТКРЫТО №8]**
- **Предсказуемость.** Одинаковая история, отчётный период и версия сценария дают одинаковый результат. Отчётный период и состав истории записываются в журнал запуска.
- **Приватность.** Данные хранятся локально или на собственном сервере. Внешние сервисы (например, ИИ) не вызываются без явного включения.
- **Язык и форматы.** Интерфейс на русском. Числа и даты в презентации в русском формате: `1 234 567,8`, «сентябрь 2026».
- **Код по желанию.** Типовые действия выполняются в конструкторе без кода. Всё остальное дописывается на Python или SQL, не выходя из приложения, и остаётся частью того же сценария.
- **Устойчивость к своему коду.** Ошибка или зависание в пользовательском коде не роняет приложение: код выполняется в отдельном процессе с ограничением по времени.
- **Изоляция ошибок.** Ошибка в одном блоке или слайде не ломает весь отчёт: проблемный слайд помечается, остальные генерируются.
- **Совместимость.** Итоговый .pptx открывается в PowerPoint 2016+, LibreOffice Impress, Keynote и импортируется в Google Slides.

## 9. Вне рамок MVP

- Несколько пользователей, роли, совместная работа **[ОТКРЫТО №2]**
- Подключение к базам данных и API вместо файлов
- Выводы от ИИ **[ОТКРЫТО №5]**
- Объединение разных источников в одном отчёте, например продаж и справочника (история одного источника в MVP есть) **[ОТКРЫТО №9]**
- Автоматический запуск по расписанию или из почты
- Прямая выгрузка в Google Slides
- Мобильная версия

## 11. Допущения и открытые вопросы

| № | Вопрос | Текущее допущение | Что изменится при другом ответе |
|---|---|---|---|
| 1 | Что меняется в новой выгрузке | Структура в целом та же; столбцы могут переименовать, добавить, убрать или переставить. Это решается сопоставлением | Если каждый раз приходит совсем другой файл, нужна привязка по смыслу столбцов и, вероятно, ИИ-сопоставление |
| 2 | Кто пользуется | Один пользователь | Авторизация, роли, PostgreSQL, общий доступ к сценариям, строгая песочница для пользовательского кода |
| 3 | Где работает | Веб-приложение в браузере, запускается локально или на своём сервере | Для программы на компьютере добавляется упаковка (Tauri или Electron) |
| 4 | Формат результата и оформление | .pptx; корпоративный шаблон загружается пользователем, есть встроенный нейтральный | Google Slides потребует интеграции с Google API; PDF добавляется конвертацией |
| 5 | Текст на слайдах | Шаблоны с подстановкой чисел | Выводы от ИИ: интеграция с LLM и отдельное решение по приватности данных |
| 6 | Точка отсчёта для «последних N дней» | Отчётный период, то есть последняя дата в выгрузке; можно переключить на дату запуска | — |
| 7 | Какие расчёты нужны | Группировки, агрегаты и сравнение с прошлым периодом (данные из истории) в MVP | Если сравнения не нужны, MVP становится меньше |
| 8 | Объём и вид файлов | До 100 тыс. строк, один лист, простая шапка | Для миллионов строк упор на потоковую обработку; сложные шапки переходят в MVP |
| 9 | Сколько источников на отчёт | Один источник с историей | Объединение разных источников (справочники) переходит в MVP |
| 10 | Повторяющиеся слайды | В v1 | При необходимости переносятся в MVP |
| 11 | Какие выгрузки приходят: за период или накопительные | За период (месяц, неделя); период определяется по столбцу с датой; новая выгрузка за уже загруженный период заменяет старую | Для накопительных выгрузок «с начала года» режим по умолчанию: каждая новая заменяет всю историю, а динамика считается внутри неё |
